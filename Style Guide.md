# Style Guide

## Goals

- Optimize for rebuilding my development environment.
- Optimize for quickly finding information after a long break.
- Explain my decisions instead of copying documentation.

## Writing Style

- Write to Future Gary.
- Keep sections concise.
- Use bullet points whenever possible.
- Explain why something exists if it isn't obvious.
- Don't duplicate information.

## Organization

- One topic per file.
- Link to related topics instead of repeating information.
- If a topic grows naturally, let it grow.
- If a page becomes too large, split it into multiple pages.

## Software

Every application should answer:

- What is it?
- Why do I use it?
- How do I install it?
- Where is it configured?

## Configuration

Configuration belongs with the software it configures.

Examples:

- Hyprland configuration → Hyprland.md
- Neovim configuration → Neovim.md
- Moonlander layout → Moonlander.md

## General Rule

If Future Gary would search for it, it belongs here.
